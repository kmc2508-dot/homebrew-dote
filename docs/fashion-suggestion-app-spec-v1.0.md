# 📱 服装提案アプリ 仕様書（Ver.1.0）

## 1. 概要
春の寒暖差で服装選びに迷うユーザーに向け、当日の気温変化に応じて「長袖 / 半袖 / 上着」の最適な組み合わせを提案する Web アプリを提供する。  
ブラウザで動作し、GitHub Pages で公開する。

---

## 2. 目的・提供価値
- 朝の服装判断を **5秒以内** で終えられるようにする。
- 日中の寒暖差による体調不良リスクを下げる。
- 服装選びにおける「迷い」と「判断コスト」を減らす。

---

## 3. ターゲットユーザー
- 寒暖差で服装選びに迷う人
- 朝の準備を短時間で済ませたい人
- 学生など、日中の気温差の影響を受けやすい人

---

## 4. 技術スタック
- フロントエンド: HTML / CSS / JavaScript
- 気象データ取得: OpenWeatherMap API（または同等 API）
- データ保存: LocalStorage
- 公開: GitHub Pages
- 通知（任意実装）: Web Notifications API / Service Worker

---

## 5. 機能要件

### 5.1 天気取得機能
**取得方法**
- 初回は Geolocation API で現在地取得を試行
- 拒否・失敗時は地名入力で取得

**取得データ（当日）**
- 最低気温
- 最高気温
- 時間帯別気温（朝・昼・夜）

### 5.2 服装提案機能（メイン）
**表示構成**
1. **メイン表示（大）**
   - 例: 「今日は長袖＋薄手の上着がおすすめ」
2. **詳細表示（時間帯別）**
   - 朝: 長袖＋カーディガン
   - 昼: 半袖でも OK
   - 夜: 長袖＋上着
3. **補足コメント**
   - 例: 「寒暖差が大きいため調節できる服装が安心です」

### 5.3 判定ロジック
#### 基本ルール（体感補正後の気温で判定）
| 気温 | 推奨 |
|---|---|
| 25℃以上 | 半袖 |
| 20〜24℃ | 半袖＋上着 |
| 16〜19℃ | 長袖 |
| 15℃以下 | 長袖＋上着 |

#### 寒暖差考慮
- 条件: `最高気温 - 最低気温 >= 7℃`
- 追加提案: 「上着を持つ」推奨を付与

#### 体感タイプ補正
- 寒がり: 判定気温を +2℃
- 普通: ±0℃
- 暑がり: 判定気温を -2℃

### 5.4 通知機能（優先度: 中、MVP外可）
**通知条件**
- 時間帯で推奨服装が変わる場合（例: 朝は長袖、昼は半袖）

**通知方式**
- 第一候補: Web Notifications API
- 可能なら: Service Worker 連携
- fallback: アプリ内バナー表示

**通知文例**
- 「気温が上がります。半袖になれる準備を！」

### 5.5 ユーザー設定機能
**設定項目**
- 体感タイプ（寒がり / 普通 / 暑がり）
- 地域（任意）
- 通知 ON/OFF

**保存方式**
- LocalStorage に保存

### 5.6 地域選択機能
- 初回: 位置情報許可を促す
- 拒否時: 地名検索に切替

## 6. 画面要件（UI/UX）

### 6.1 コンセプト
- 一目でわかる
- 朝5秒で判断できる

### 6.2 画面構成
1. **ホーム画面**
   - 今日の服装（大きく表示）
   - 時間帯別提案
   - 気温（最低/最高/時間帯）
2. **設定画面**
   - 体感設定
   - 通知設定
   - 地域変更

### 6.3 デザイン方針
- 温度感を色で表現
  - 暖色: 暑い
  - 寒色: 寒い
- アイコン活用
  - 👕 半袖
  - 🧥 上着
- スマホファーストのレスポンシブ設計

---

## 7. データ設計（LocalStorage）

### 7.1 保存データ構造
```json
{
  "userType": "cold | normal | hot",
  "location": "tokushima",
  "notifications": true
}
```

### 7.2 キー例
- `appSettings`: 設定オブジェクト
- `lastLocation`: 最終取得地点（任意）

---

## 8. API 設計
- 利用候補: OpenWeatherMap `/forecast`
- 目的: 3時間ごとの気温データを取得し、朝/昼/夜に再集約
- エラーハンドリング:
  - API 失敗時は「取得失敗」の明示
  - 最終取得データがあれば暫定表示（任意）

---

## 9. 非機能要件
- レスポンシブ対応（スマホ / PC）
- 初回ロード 3 秒以内（目標）
- API エラー時に fallback UI を表示
- GitHub Pages 上で静的配信可能な構成にする

---

## 10. MVP（最初に作る範囲）
1. 天気取得（位置情報 + 地名入力 fallback）
2. 服装判定ロジック（体感補正 + 寒暖差判定）
3. 結果表示（メイン + 時間帯別詳細 + 補足）
4. ユーザー設定保存（LocalStorage）

> 通知機能は MVP 後に段階導入で可。

- ユーザーが当日の推奨服装をトップ画面で即時確認できる
- 朝/昼/夜の提案が表示される
- 体感設定を変更すると判定結果に反映される
- ページ再訪時に設定が保持される（LocalStorage）
- 位置情報拒否時でも地名入力で利用継続できる
